# Resident numeric LightGBM prediction

`lightgbm_t%predict_device` now lowers every fitted finite numeric tree to the
resident additive-tree CUDA ABI used by the XGBoost numeric path. Leaf-wise
growth remains a LightGBM CPU fitting policy. Only the fitted topology and
per-round tree scales are transferred to the native plan. A binary model
applies its sigmoid link after resident raw-margin evaluation.

The ordinary build returns `FORTNUM_NOT_IMPLEMENTED` when the native CUDA ABI
is unavailable and preserves the caller's output. It never labels a host
prediction as CUDA work. Categorical nodes, missing-value routing, and
histogram construction are not part of this ABI and remain explicit follow-up
contracts.

`test_lightgbm_cuda_dispatch` compares a one-split fit with an independent
Newton tree oracle, checks CPU dispatch, and accepts either resident CUDA
parity or the typed unavailable boundary. The benchmark release lane is
[`LIGHTGBM_CUDA.md`](../fortml-bench/results/LIGHTGBM_CUDA.md), generated by
`scripts/bench_lightgbm.py`.
